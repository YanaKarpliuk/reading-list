# Reading List API

A small REST API for keeping track of books you want to read, are reading, or have finished.
Built with plain Node.js (no frameworks) as a learning project.

> **Note:** books are stored in memory. Every server restart (including the automatic
> restarts from `npm run dev`) resets the list to the 3 seeded books with **new IDs**.

## Requirements

- Node.js **18.11 or newer** (for `node --watch`). The project pins Node 24 in `.nvmrc`.
- `curl` for trying out requests. `jq` is optional, for pretty output.

## Getting started

```bash
nvm use        # switch to the Node version from .nvmrc
npm run dev    # start the server and restart it on every file save
```

The server runs at http://localhost:3000.

| Script        | What it does                         |
| ------------- | ------------------------------------ |
| `npm run dev` | Starts the server in watch mode      |
| `npm start`   | Starts the server without watching   |

## Data model

| Field       | Type   | Notes                                                    |
| ----------- | ------ | -------------------------------------------------------- |
| `id`        | string | UUID, set by the server                                  |
| `title`     | string | **Required**, must not be empty                          |
| `author`    | string | Optional                                                 |
| `status`    | string | One of `want`, `reading`, `done`. Defaults to `want`     |
| `createdAt` | string | ISO 8601 date, set by the server                         |

`id` and `createdAt` are always generated by the server. If a client sends them, they are ignored.

## Endpoints

| Method   | Path                   | Description                    | Success          |
| -------- | ---------------------- | ------------------------------ | ---------------- |
| `GET`    | `/books`               | List all books                 | `200`            |
| `GET`    | `/books?status=<s>`    | List books with a given status | `200`            |
| `GET`    | `/books/:id`           | Get one book                   | `200`            |
| `POST`   | `/books`               | Create a book                  | `201`            |
| `PATCH`  | `/books/:id`           | Update some fields of a book   | `200`            |
| `DELETE` | `/books/:id`           | Delete a book                  | `204` (no body)  |

`GET /` returns the same list as `GET /books` and also accepts `?status=`.

Errors are returned as JSON: `{ "error": "message" }`.

| Status | When                                                         |
| ------ | ------------------------------------------------------------ |
| `400`  | Invalid JSON, a failed validation, or an unknown `status` filter |
| `404`  | Unknown book ID or unknown route                             |

## Using the API with curl

Useful curl flags:

- `-i` shows the status line and headers, not just the body
- `-s` hides the progress meter
- `-X METHOD` sets the HTTP method (`POST`, `PATCH`, `DELETE`)
- `-H 'Header: value'` adds a request header
- `-d '...'` sends a request body

Always put URLs that contain `?` or `&` in quotes.

### List all books

```bash
curl -i http://localhost:3000/books
```

Pretty-printed with `jq`:

```bash
curl -s http://localhost:3000/books | jq
```

### Filter by status

```bash
curl -i "http://localhost:3000/books?status=reading"
curl -i "http://localhost:3000/books?status=want"
curl -i "http://localhost:3000/books?status=done"
```

An unknown status gives a `400`:

```bash
curl -i "http://localhost:3000/books?status=banana"
# {"error":"status must be one of: want, reading, done"}
```

### Create a book

```bash
curl -i -X POST http://localhost:3000/books \
  -H 'Content-Type: application/json' \
  -d '{"title": "Project Hail Mary", "author": "Andy Weir", "status": "reading"}'
```

Only `title` is required. `status` defaults to `want`:

```bash
curl -i -X POST http://localhost:3000/books \
  -H 'Content-Type: application/json' \
  -d '{"title": "Neuromancer"}'
```

The response (`201 Created`) contains the new book with its `id`. Copy the `id` for the next requests.

### Save an ID in a shell variable

IDs are random and change on every restart, so it's handy to store one in a variable.
With `jq`:

```bash
ID=$(curl -s -X POST http://localhost:3000/books \
  -H 'Content-Type: application/json' \
  -d '{"title": "Test Book"}' | jq -r '.id')
echo $ID
```

Without `jq`, copy the `id` from the response by hand:

```bash
ID=paste-the-id-here
```

The examples below use `$ID`.

### Get one book

```bash
curl -i http://localhost:3000/books/$ID
```

### Update a book

Send only the fields you want to change:

```bash
curl -i -X PATCH http://localhost:3000/books/$ID \
  -H 'Content-Type: application/json' \
  -d '{"status": "done"}'
```

```bash
curl -i -X PATCH http://localhost:3000/books/$ID \
  -H 'Content-Type: application/json' \
  -d '{"title": "A Better Title", "author": "Someone"}'
```

### Delete a book

```bash
curl -i -X DELETE http://localhost:3000/books/$ID
# HTTP/1.1 204 No Content
```

Check that it's gone:

```bash
curl -i http://localhost:3000/books/$ID
# HTTP/1.1 404 Not Found
# {"error":"Book not found"}
```

### Error examples

Broken JSON:

```bash
curl -i -X POST http://localhost:3000/books -d '{"title": "Dune",'
# 400 {"error":"Invalid JSON"}
```

Empty title:

```bash
curl -i -X POST http://localhost:3000/books -d '{"title": ""}'
# 400 {"error":"title is required and must be a non-empty string"}
```

Invalid status:

```bash
curl -i -X POST http://localhost:3000/books -d '{"title": "Dune", "status": "lost"}'
# 400 {"error":"status must be one of: want, reading, done"}
```

Unknown ID:

```bash
curl -i http://localhost:3000/books/made-up-id
# 404 {"error":"Book not found"}
```

Unknown route:

```bash
curl -i http://localhost:3000/anything
# 404 {"error":"Not found"}
```
